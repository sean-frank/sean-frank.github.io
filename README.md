# Sean Frank

Personal site for Sean Frank. GitHub Pages builds it with the native Jekyll environment (github-pages gem, whitelisted plugins only). No Actions workflow is required.

## Local build

```bash
bundle install
JEKYLL_ENV=production bundle exec jekyll build
```

## Placeholders

- Résumé links point at `/resume.pdf`. Add the file as `resume.pdf` in the repo root.
- Certifications live in `_data/certifications.yml`. The section stays hidden while that list is empty.
- Projects live in `_data/projects.yml`. An empty list shows an empty state.
- Focus tags live in `_data/focus.yml`. The same list is `knowsAbout` in the JSON-LD.
- Profiles are only the email, GitHub username, and LinkedIn username in `_config.yml`.
- Search Console and Bing verification tokens go in `_config.yml` under `webmaster_verifications` (`google` and `bing`). The meta tags are omitted until those values exist.
- In a post, put the title in front matter and start the body at a second-level heading so the page keeps a single `h1`. `titles_from_headings` is disabled so that front matter title is the one that is published.

## Search files

- `/robots.txt` allows every crawler, including GPTBot, OAI-SearchBot, ChatGPT-User, PerplexityBot, ClaudeBot, Google-Extended, and Applebot-Extended, and points at the sitemap.
- `/sitemap.xml` is generated by jekyll-sitemap.
- `/llms.txt` is a plain-text summary for language models.
- Home page JSON-LD describes a Person, a WebSite, and a ProfilePage. Posts add a BlogPosting.

## Dinner recipes (`/cook/`)

Hidden pages for Apple HomeView Start Cooking. Safari can open them. They send `noindex, nofollow`, they are left out of the sitemap and the Atom feed, and nothing on the public site links to them. Do not add a `Disallow` for `/cook/` in `robots.txt`.

Add a Markdown file in `_cook/` (the file name becomes the URL slug). `_config.yml` already sets `layout: recipe`, `sitemap: false`, and `robots: noindex, nofollow` for that collection. The page body is ignored. The visible page and the schema.org Recipe JSON-LD are both rendered from this front matter:

```yaml
---
name: Weeknight chili
description: One serving of chili.
date: 2026-11-18
today: false
yield: "1 serving"
prep_time: PT10M
cook_time: PT30M
total_time: PT40M
category: Dinner
tools:
  - skillet
ingredients:
  - 1 teaspoon salted butter
steps:
  - name: Brown the meat
    text: Brown the meat in butter for 8 minutes. Start an 8-minute Beef timer.
---
```

`prep_time`, `cook_time`, and `total_time` are ISO 8601 durations (`PT10M`, `PT1H`, `PT1H30M`). Each step is one action. State durations in plain words, and where a timer helps include a sentence like `Start a 10-minute Name timer`.

`date` is the day that dinner is cooked. `_config.yml` sets `future: true` so a recipe dated later in the week is still published.

Set `today: true` on exactly one recipe. `/cook/today/` redirects there (newest `today` recipe if more than one is marked). If none is marked, it redirects to the newest recipe by date. `/cook/` lists every recipe, newest first, so it can be bookmarked.
